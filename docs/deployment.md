# Deployment and cost notes — AWS UNVERIFIED

No AWS account is used and no resources are created by setup. `serverless.yml` defines Python 3.12 upload API, S3 versioning/encryption/public-access block, TLS-only bucket policy, ObjectCreated→SQS, source-account/ARN-scoped queue policy, partial batch failure ingestion, DLQ, bounded Lambda concurrency, and a scheduled outbox dispatcher. Visibility timeout is 720 seconds for a 120-second ingestion function. Distinct roles scope upload, ingestion and dispatch application permissions; the managed VPC execution policy supplies EC2 network/log permissions and should be further narrowed after deployment requirements are known.

## Manual prerequisites

1. Choose an AWS account/region and approve costs. Estimate RDS instance/storage/backups, NAT or interface endpoints, private compute for n8n/API, Lambda, SQS, S3 and SES charges using current AWS pricing. No zero-cost RDS guarantee is possible.
2. Create a VPC with two private subnets and a private RDS PostgreSQL instance. Disable public access. Enable encryption, backups, deletion protection and TLS. Limit inbound 5432 to Lambda/private application security groups. Use RDS Proxy if concurrency grows. Create a least-privilege application DB role and run Alembic from a VPC-connected migration host.
3. Host n8n and the matching/notification FastAPI service on private compute in that VPC. Put the n8n editor behind a VPN/identity proxy. Supply `param:n8nPrivateUrl`. Private routes must resolve and connect from the dispatcher. The public upload Lambda has no n8n internal routes registered in API Gateway.
4. Provide S3 access through a gateway endpoint. Add NAT or appropriate private endpoints only where necessary. SES needs outbound network access. DB migrations and service initialization must precede ingestion triggers. Do not use Docker localhost addresses in AWS.
5. Set `/loan/<stage>/database-url`, `api-token`, and `workflow-secret` SSM SecureString values. Configure the DB URL with TLS verification and CA certificate. Set the same workflow secret on the private API and n8n credential. Keep API bearer tokens server-side in a production authenticated frontend; the local operator UI is not a multi-user authorization design.
6. Build the Lambda artifact on Linux for Python 3.12 with `scripts/package_lambda.ps1`. Review package contents. Install Serverless Framework v4 separately and review its authentication/licensing requirements. Use a locked CLI version after validating it; this repository does not claim a tested Serverless deployment toolchain.
7. Explicitly supply deployment parameters: `n8nPrivateUrl`, `testInbox`, `lambdaSecurityGroup`, `privateSubnetA`, `privateSubnetB`, `frontendOrigin`. Run `serverless print`/`serverless package` with the chosen stage/region, review CloudFormation/IAM, then deploy only after the user approves. SSM/CloudFormation resolution requires authenticated AWS access.
8. Validate actual S3 uploads, SQS retries/DLQ, RDS migrations, private n8n reachability, callbacks, logs, and recipient safety. Cloud integration remains UNVERIFIED until those runs are recorded.

## SES test integration

Local preview uses Mailpit. For a separately approved real test, verify sender and controlled recipient in SES (sandbox restrictions apply), set `EMAIL_DELIVERY_MODE=test`, `SES_SENDER`, and `NOTIFICATION_TEST_INBOX` on the private notification service. Grant that service `ses:SendEmail` scoped to the verified sender identity and an SES recipient condition for the controlled inbox. Do not give this permission to ingestion/upload Lambdas. The template defaults to preview and does not provision this permission or SES identities. Do not claim inbox receipt from a successful SDK return; capture actual inbox evidence after approval.

References: [Lambda partial SQS failures](https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-errorhandling.html), [RDS PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/CHAP_PostgreSQL.html), [n8n Docker hosting](https://docs.n8n.io/hosting/installation/docker/), [MinIO pinned source release](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z).

## Local packaging evidence (not deployment)

The revised `scripts/package_lambda.ps1` invokes `scripts/package_lambda.py` and sends build code to the SAM container over stdin, avoiding Windows nested-shell quoting. It caches downloaded wheels in Docker volume `loan-engine-lambda-pip-cache`, mounts sources read-only, and writes `.serverless/loan.zip` (ignored by Git and Docker builds). Run `python scripts/verify_lambda_artifact.py` afterward. `reports/lambda-package.json` records the build image ID/hash; `reports/lambda-artifact.json` records the runtime image ID, source equality, native imports, local ASGI responses and artifact sizes. The manifests record the measured zip and uncompressed sizes for each build. This is a local AWS base-container smoke; it performs no cloud calls and does not validate RDS, IAM, event delivery or SES. The SAM/runtime tags and transitive requirements still need a locked release process.
