# Security and reliability boundaries

Local services bind to 127.0.0.1. This is a single-operator development environment. API bearer tokens and shared workflow secrets are randomly generated in `.env`; browser tokens live only in memory. No credentials appear in workflow exports. HTTPS and an identity-aware proxy are required before exposing any service beyond loopback. Current per-process rate limiting is deliberately basic; use gateway/WAF limits and identity-scoped authorization for production.

Uploads use generated keys, a five-minute presigned PUT, content length/type and create-only headers. The worker checks size, SHA-256, strict UTF-8, exact headers and row schemas. Fatal errors roll back the entire ingestion. CSV exporters must call `safe_csv_cell`; no export endpoint is currently exposed. Parameter binding is used for job IDs in SQL. Fixture and extracted source URLs require HTTPS. Unapproved sources cannot be fetched through the discovery endpoint. Secrets and private CSVs are Git/Docker ignored.

The API defaults to same-origin requests and does not grant arbitrary CORS access. MinIO's browser CORS origin is limited to the dashboard origin. Production S3 CORS is parameterized. HTML email values are escaped; product URLs are schema-validated and stored from configured sources. Notification recipient selection accepts no sample-user input. Only preview or explicitly configured SES test delivery modes exist. A configured destination that collides with any ingested source email is rejected; SES test bodies use a synthetic first name. Gmail plus aliases can be used by setting the one controlled inbox address; no aliases are synthesized from sample addresses.

Compose uses the bootstrap PostgreSQL superuser for the application and n8n metadata. This is a local convenience, not a production privilege model. Use separate non-superuser roles before deployment. The n8n domain-query credential is separately restricted to required eligibility columns; runtime checks confirm that names and email addresses are denied. Code-node environment access is enabled for DEMO_MODE, so editor access must remain restricted to trusted operators.

Production credentials belong in SSM SecureString/Secrets Manager, with encryption and rotation. Serverless deployment resolves SSM values; access to deployment logs, generated CloudFormation and Lambda environment configuration must be restricted. Lambda database pools cap at two connections per process; concurrency caps and/or RDS Proxy bound total connections. Configure TLS certificate verification for RDS (`sslmode=verify-full` and an approved CA bundle), private subnets and database security groups permitting 5432 only from application/Lambda security groups. Do not expose PostgreSQL or n8n directly.

Unknown email submissions and stale SENDING rows require operator reconciliation; provider exactly-once delivery is impossible to guarantee with SMTP/SES alone. Job error records omit raw rows and addresses. Retain local CSV/object/database snapshots only as long as needed; production bucket retention is seven days, while database PII retention/deletion needs an explicit operational policy. DB backups, application IAM credentials, monitoring alarms, tenant authorization, container/image qualification and penetration/load tests remain production work. The Python runtime requirements have a bounded known-vulnerability scan; that does not certify the entire stack.
