# Design decisions

- **Snapshot users per job:** replaying an identical event is a no-op, while a new upload remains a new historical observation. External IDs are unique inside an ingestion job, not globally.
- **PostgreSQL bulk inserts:** portable through SQLAlchemy's PostgreSQL dialect, bounded at 500 rows; no per-user INSERT loop. COPY is an optional future throughput optimization.
- **Single ingestion transaction:** keeps error counts, snapshots and outbox consistent. The 20 MB file cap bounds work. Large production files need staging/checkpoints and load tests before raising that limit.
- **n8n stage evaluation with backend revalidation:** Workflow B runs SQL in a Postgres node and reusable qualitative/unknown-rule evaluation in a Code node. The backend reruns the structured query and checks every proposed outcome before transactional bulk persistence. This adds query cost but catches drift between extraction and persistence and prevents unsupported candidates. n8n reads at most 1,000 candidates per ordered keyset page. A locked audit stores the cursor, counters and criteria fingerprint. Duplicate or concurrent pages cannot increment progress twice, changed criteria stop the job, and C remains blocked until the final empty/short page and B acknowledgement. No schema migration is required. Historical completed jobs and the existing bulk endpoint remain compatible.
- **Optional LLM, disabled by default:** set `LLM_ENABLED=true`, `GEMINI_API_KEY` and an explicitly chosen `GEMINI_MODEL` only after approved source access and separate authorization for API use. The Gemini REST adapter accepts approved public product text only, caps input at 12,000 characters, output at ten verbatim quotes, one concurrent call and at most three attempts per API process by default (`LLM_MAX_CALLS_PER_PROCESS`, maximum 20). Its strict local schema rejects extra fields and unsupported quotes. Failed or unavailable extraction leaves unknown requirements uncertain; live products remain UNVERIFIED. It cannot change hard numerical rules or approve a match. Fixtures never call it. Credentials and a successful live call are not verified; budgets reset on process restart and are not a distributed cost limit.
- **Conservative discovery:** accessibility does not establish automation permission. Sources default to disabled, and all auto-extracted live values are UNVERIFIED. Fictional fixtures are operationally distinct.
- **Email uncertainty:** SMTP/SES cannot participate in the database transaction. Ambiguous outcomes stop for reconciliation rather than risking duplicate submission. This sacrifices automatic transient delivery recovery when acceptance is unknown.
- **Source-build MinIO:** upstream container pulls failed. A pinned official source release with its matching Go toolchain is built locally. The local development storage service is not a production support recommendation.

- **Immutable matching decision jobs:** a matching version change requires a new upload job. Existing completed jobs retain their original audit; the service rejects silently reusing an old audit under a different code version.
- **n8n history:** successful pseudonymous execution payloads are retained for 24 hours for runtime evidence. The initial none retention setting left observed execution metadata marked running even after service work finished; final verification uses all retention. PostgreSQL 16 receives compatibility support only from n8n 2.43.6; use PostgreSQL 17+ for fresh production infrastructure.

- **SES-node attempt ownership:** the optional C branch claims one durable event, marks SENDING before handing it to the official SES node, and records a MessageId through an authenticated callback. Node retries are disabled and the exported node itself is disabled. A lost claim/receipt is not a reason to resend; UNKNOWN and stranded SENDING require reconciliation. The service SDK also permits only one send attempt. These controls do not promise provider exactly-once delivery or make manually rerunning a selected SES node safe.
