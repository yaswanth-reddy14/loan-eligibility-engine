# Workflow import and operation

Pinned target: n8n **2.43.6**. Exports contain only official Webhook, Schedule Trigger, Manual Trigger, HTTP Request, Code IF and Postgres nodes. `scripts/validate_workflows.py` checks JSON structure/connections; it cannot establish runtime compatibility by itself.

After `docker compose up -d --build`, run with the local Python environment and PYTHONPATH=backend:

```powershell
.\.venv\Scripts\python scripts/import_n8n.py
```

The script imports a local header credential over stdin into a short-lived container file with mode 0600, deletes it after import, imports all three exports, publishes A, B and C, and restarts n8n. The credential is `Loan internal header` (ID `loan-internal-header`), type Header Auth, header name `X-Workflow-Secret`, value from `.env`. No decrypted credential export is committed. If CLI publication differs in your installed version, use the editor Publish control for B/C and restart the dispatcher only after both webhooks are registered.

Manual UI import: select each JSON under `n8n/workflows/`, configure that same Header Auth credential on webhook/HTTP nodes, and publish A/B/C. Workflow IDs are `loan-workflow-a`, `loan-workflow-b`, `loan-workflow-c` when using the supplied CLI import. Paths: `POST /webhook/loan-b`, `POST /webhook/loan-c`. Requests without the configured header must be rejected. The webhook returns acceptance immediately; inspect service audit rows and n8n execution metadata for actual completion.

A's schedule is daily at 09:00 Asia/Kolkata, but A is published with all live sources disabled. Three source candidates fail closed at the permission gate and produce crawler audit rows. Its manual branch and authenticated `/webhook/loan-a-demo` branch fetch three bundled fictional HTML pages through HTTP, then normalize, extract, validate and upsert them. The dashboard discovery button invokes that webhook through the authenticated API. Fixture extraction accepts only the bundled HTML and requires DEMO_MODE. Review robots, page accessibility and published usage restrictions, record evidence/date, add source-specific extraction tests, and update both `n8n/sources.json` and generated exports before enabling any live source. Run `python scripts/generate_workflows.py` after source configuration edits. A source extraction is not lender verification; live products remain UNVERIFIED.

B checks UUID-shaped job ID and completed metadata, runs parameterized SQL in its Postgres node, evaluates advanced rules using n8n/advanced_rules.js, and submits outcomes for backend revalidation and bulk persistence. A dedicated read-only PostgreSQL credential is created by the import script; manually configure ID loan-domain-postgres for UI imports. Filtered candidates are pseudonymous and capped at 50,000 per job. B persistence records PERSISTED; its final acknowledgement node marks B COMPLETED and creates C's outbox event; it never claims success simply from HTTP acceptance. C verifies B completion, selects grouped unnotified users, and calls the allowlisted delivery service in batches of 100. Repeated webhook deliveries are idempotent; pending batches are drained by dispatcher retries. Original email addresses never enter n8n execution data.

Credentials and workflow publication are persistent in PostgreSQL/n8n volumes. Encryption key must be preserved between restarts. Execution payloads contain pseudonymous IDs and product criteria, never user email addresses or names, and are pruned after 24 hours. Successful payloads are retained to support execution evidence and avoid observed stale running metadata when success storage was disabled. A related upstream report is https://github.com/n8n-io/n8n/issues/38551; that report does not establish the exact cause of this instance's behavior. The local stack is loopback-only and uses HTTP; production requires private connectivity and TLS. The SQL node needs the read-only PostgreSQL credential. SES stays in the authenticated notification service and does not require an n8n SES credential. Set DEMO_MODE=true only for local fixture matching; production must use false.

The domain reader receives SELECT only on users.id, job_id, monthly_income, credit_score, employment_status and age, plus product/criteria tables. Names and contact email are denied at column privilege level. `reports/n8n-db-permissions.json` records the candidate query and denial check for the reviewed local role.
